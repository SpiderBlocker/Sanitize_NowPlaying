Standalone RDS metadata processing · v3.0.0

Sanitize NowPlaying

A standalone Windows 10/11 application that monitors playout metadata and transforms noisy artist/title text into clean, predictable RDS RadioText, RT+ and separate prefix, artist, connector and title output files. v3.0.0 is a complete C# / .NET Framework 4.8 WinForms rewrite and the direct successor to the PowerShell/conhost v2.1.8 release.

Download v3.0.0 GitHub repository

Purpose-built for RDS

Continuously watches playout metadata, removes common library noise, applies RDS-aware length rules and keeps on-air text predictable without requiring an entire music library to be retagged.

Six atomic outputs

Use ready-made RT/RT+ files or separate prefix, artist, connector and title component files. Each output file is UTF-8 without BOM and is replaced atomically.

Standalone WinForms UI

No PowerShell or console host is required. The graphical v3 interface provides live status, an F10 Settings overlay, draggable nested menus, folder selection and first-run setup.

v3.0.0 continues the v2.1.8 lineage

v3 is a rewrite, not a new product. The existing settings schema, output filenames and processing contract were deliberately retained, and v3 processing was regression-tested against the final v2.1.8 PowerShell reference.

Typical signal path

1. Playout softwareWrites artist/title metadata to the configured input file; nowplaying.txt remains the default.
2. Sanitize NowPlayingNormalizes text, removes metadata noise and applies the selected presentation settings.
3. Output filesWrites ready-made RT/RT+ plus separate prefix, artist, connector and title files.
4. RDS softwareStereo Tool, Magic RDS 4 or another workflow reads the complete outputs or component files.

Designed for live use

  • Hybrid event-driven input monitoring
  • Startup freshness handling
  • Atomic writes and automatic retries
  • Single-instance protection
  • Fail-safe settings commits
  • Output clearing on shutdown

Metadata handling

  • Artist/title cleanup and conservative splitting
  • Balanced (), [] and {} handling
  • Configurable prefix, connector and delimiter
  • Optional Greek/Cyrillic transliteration and ASCII-safe mode
  • Independent 64-character artist/title limits
  • Adaptive compact RT/RT+ trimming

Operational resilience

  • Mapped-drive and UNC Working Directory recovery
  • OFFLINE state without silent local fallback
  • Configurable input filename
  • Delayed split-write protection
  • Per-file write-failure reporting
  • Stereo Tool or Magic RDS 4 RT+ syntax

Quick start

Download the ZIP, extract it to a writable directory and run SanitizeNowPlaying.exe. On first start, select the Working Directory used by the playout system. Then configure the playout software to write its artist/title metadata to the selected input file and point the RDS software to the generated RT/RT+ or component files.

The application stores Sanitize-NowPlaying.settings.json next to the executable. Windows 10/11 and .NET Framework 4.8 are required.

Stereo Tool component example

The separate component files can be combined as an alternating RadioText sequence:

5s:\r"C:\RDS\prefix.txt"/10s:\+AR\r"C:\RDS\artist.txt"\-/5s:\r"C:\RDS\connector.txt"/10s:\+TI\r"C:\RDS\title.txt"\-

Synchronization note: Stereo Tool reads component files when the individual section becomes active rather than taking one shared snapshot. Use the ready-made RT/RT+ files when guaranteed artist/title consistency is more important than separate component rotation.
