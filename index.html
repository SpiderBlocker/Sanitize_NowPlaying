Standalone RDS metadata processing · v3.1.1

Sanitize NowPlaying

A standalone Windows 10/11 application that monitors playout metadata and transforms noisy artist/title text into clean, predictable RDS RadioText, RT+ and separate prefix, artist, connector and title output files. v3.1.1 refines rule interactions, RT/RT+ shortening and consistent menu behavior, with matching explanatory help and reliable native tooltips.

Download v3.1.1 GitHub repository

Purpose-built for RDS

Continuously watches playout metadata, removes common library noise, applies RDS-aware length rules and keeps on-air text predictable without requiring an entire music library to be retagged.

Six atomic outputs

Use ready-made RT/RT+ files or separate prefix, artist, connector and title component files. Each output file is UTF-8 without BOM and is replaced atomically.

Standalone WinForms UI

No PowerShell or console host is required. The graphical v3 interface provides live status, five quick menus, an F10 Settings overlay, draggable nested menus, folder selection and first-run setup.

Typical signal path

1. Playout softwareWrites artist/title metadata to the configured input file; nowplaying.txt remains the default.
2. Sanitize NowPlayingNormalizes text, removes metadata noise and applies the selected presentation settings.
3. Output filesWrites ready-made RT/RT+ plus separate prefix, artist, connector and title files.
4. RDS softwareStereo Tool, Magic RDS 4 or another workflow reads the complete outputs or component files.

Quick start

Download the ZIP, extract it to a writable directory and run SanitizeNowPlaying.exe. On first start, select the input folder used by the playout system. Output follows that folder by default; choose a separate destination in F10 Output settings if needed. Configure the playout software to write artist/title metadata to the selected input file and point the RDS software to the generated RT/RT+ or component files. In F10, Save & exit applies the draft; closing changed settings offers Save & exit, Discard changes or Cancel.

The application stores Sanitize-NowPlaying.settings.json next to the executable. Windows 10/11 and .NET Framework 4.8 are required.

Stereo Tool component example

The separate component files can be combined as an alternating RadioText sequence:

5s:\r"C:\RDS\prefix.txt"/10s:\+AR\r"C:\RDS\artist.txt"\-/5s:\r"C:\RDS\connector.txt"/10s:\+TI\r"C:\RDS\title.txt"\-

Synchronization note: Stereo Tool reads component files when each section becomes active rather than taking one shared snapshot, so a sequence can mix components from adjacent tracks. Each ready-made RT or RT+ file contains one complete combined payload and avoids that rotation issue. The six output files are still replaced independently.
